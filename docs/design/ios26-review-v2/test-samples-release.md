# 下一次 iPhone 测试版：可操作的社区猫样本

2026-09-08 · 已纳入下一版范围，尚未导入服务器或发布安装包。

用户目标：首次打开就能看到有照片、有历史的猫，并实际测试发现、档案、关注、目击和照护。样本必须由同一套服务读取，不能只把静态卡片写死在手机里。

## 先复用真实记录，再补足测试场景

优先选择已有、获准公开且符合当前公开投影规则的社区猫。真实记录不足时，默认在测试环境补充标注“测试样本”的合成档案。真实猫与合成猫的来源分别保存，不能给真实猫编造目击、照护、确认或活跃状态。

目前尚未核实线上公开猫数量和可用公开照片。现有发现/档案摘要契约没有可显示的照片 URL；公开动态的 coverMediaId 也不等于可访问的图片。设计稿的阿橘照片是合成素材，不是用户已上传的真实社区猫。

## 最小有用样本集

以下是覆盖目标，不是已经存在或上传成功的数据清单。已有真实记录满足条件时直接复用，不重复创建。

| 样本场景 | 必须能看到或执行的内容 |
| --- | --- |
| S01 近期活跃、有照片 | 主照片、已公开目击、已完成照护；可关注、追加目击和照护 |
| S02 同一区域的另一只猫 | 独立照片、独立动物 ID；验证列表不会混猫、关注状态独立 |
| S03 另一区域、有历史 | 可筛选到、可打开历史、跨页面仍对应同一只猫 |
| S04 第三个区域、多次活动 | 多条公开活动；排序和详情一致，不显示精确位置或伪造实时在线 |
| S05 无公开照片 | 完整缺图布局，仍可打开档案和贡献；不套用其他猫的照片 |
| S06 较早活动或待确认 | 正确显示真实状态；无新活动不暗示无人照护，待确认不冒充已确认 |

建议总量 6 只、至少 4 只具有独立可公开照片，覆盖现有 3 个支持区域。每只活跃样本至少有 2 条已经允许公开的活动，覆盖目击和照护。所有合成时间相对导入时间生成，并遵守现有延迟公开规则；不靠关闭规则制造活跃数据。

## 连续实施顺序

1. **照片和来源接通（随 U1）**：完成公开照片读取契约与移动端接线，包含缺图/失败回退。核对选中素材的公开许可、人工遮挡和可见资格；不得直接暴露私有原图或用图库搜索结果冒充已上传社区猫。
2. **准备一次可重复的测试数据导入（随 U1/U2）**：先输出选中真实记录和缺少场景的清单，再在指定测试环境补足。稳定样本 ID、来源标记、独立图片引用；重复执行不新增重复猫或历史。沿用已有创建/公开流程，不虚构审核人。脚本拒绝生产环境，不重置数据库；清理仅操作本批样本和明确属于本批的测试记录。
3. **同一候选包交付（随 U3）**：安装后确认从服务取到样本，附样本名单与可测试动作。公开商店发行前移除或隔离合成样本；它们不是实际社区活跃量或训练评测数据。

## 一次必要回归，直接在用户的 iPhone 验收

- 冷启动：附近显示可公开样本，至少一张照片真正加载；区域筛选和地图能打开同一档案。
- 登录后关注 S01：关注列表出现；杀掉应用重开仍保留；取消后消失。
- 为 S01 新增一次目击和已完成照护：本人回执成功、重试不重复；本人能读到，公共活动按实际公开时机显示。
- S05 无图仍可用；断网后出现真实错误和重试，恢复后图片/列表加载正常。
- 回看三处原生玻璃：滚动中的底栏、地图浮层、照片上的返回/关注；切换深色与“减少透明度”，文字仍清晰。

组件改动跑受影响测试；照片/导入涉及的服务权限与幂等各验证一次；批末复用项目现有必要回归。六只猫不是六套独立门禁，也不新增全仓审计流程。
