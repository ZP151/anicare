# 下一次 iPhone 测试

目标：先确认页面和内容可用，再验证最短贡献闭环。设计参考为 [iOS 26 v2](design/ios26-review-v2/index.html)。不需要逐张验收 87 个状态。

## 安装

使用已安装的 Sideloadly，选择本次交付的 IPA 和同一 Apple ID 更新应用。安装包路径、版本和构建结果将在交付后附于下方。不要先卸载旧应用，以免丢失尚未提交的本地草稿。

## 约 10–15 分钟的核心流程

1. **附近与档案**：保持默认“所有身份状态”（测试样本未假装为人工确认）。冷启动后看到明确标注的测试猫及照片；切换区域，再打开猫详情。记录页面是否仍显得拥挤、照片是否完整、图标是否清楚。
2. **毛玻璃**：在附近页上下滚动，查看内容经过底栏时的材质；查看地图浮层和照片上的按钮。系统“减少透明度”打开时应清晰实色，关闭后恢复材质。
3. **个人资料**：打开“我的”→编辑个人资料，修改昵称保存并返回。确认登录、语言和个人资料有各自清晰的页面层级，不再堆在首页。
4. **关注**：登录后关注一只测试猫；到关注列表打开它，关闭应用重开，再取消关注。
5. **目击**：从同一猫档案开始记录；中途保存草稿并返回，再恢复并提交。先测试无照片路径，随后可测试照片人工遮挡与上传；以回执显示的实际结果为准。
6. **照护**：为同一只猫记录已经完成的观察或补水，在“我的照护”确认。公共历史有延迟，本人记录和公共历史不要混淆。

有余力再切换深色、大字号和断网重试。反馈用“页面/图号 + 操作 + 实际结果”即可，例如“E01 保存昵称后返回仍显示旧昵称”。
