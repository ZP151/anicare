## 0.2.0（4）本轮验收重点

用户已对 0.1.2（3）做过初测：部分功能可用；“开始报告”提示已保存报告无法使用。下方旧构建记录保留为历史。本轮修复与设计见 [新加坡社区 v3](plans/2026-09-09-singapore-community-v3.md) 和 [8 张增量稿](design/ios26-review-v3/index.html)。新 IPA 的交付结果另记，未把自动化通过当成真机通过。

1. **先测报告修复**：点“报告 → 开始报告”，应进入向导。先完成无照片路径；保存退出后恢复，不再显示“这份已保存的报告无法使用”。再分别点定位、拍照、图库，只在使用时申请权限；拒绝后仍可手选地点或去设置恢复。
2. **新加坡地图**：切换中部、东部、北部、东北部、西部；搜索 Woodlands / Tampines / Mochi。点社区计数标记，核对列表、HDB / Condo 名称、猫档案和“社区足迹”跳转。计数是当前载入的延迟活动，不是该社区全部真实猫数。
3. **公开楼栋**：报告中填写一个明确标记的测试 HDB 大牌或 Condo 项目名。检查提交回执；公共位置不会立即出现，正常活动延迟两小时、敏感活动 24 小时。临界风险内容不公开。报告者填写的名称不等于已核实猫的住址。
4. **个人资料**：修改昵称并选择猫咪、爪印、绿叶、太阳、月亮或爱心头像；保存后返回并重开应用，检查一致性。
5. **社区讨论**：从地图或猫档案进入，发布测试讨论并回复；关闭重开仍存在。用同一 iPhone 依次切换两个账号即可检查参与和回复；自己的内容可以删除，他人的内容可以举报或屏蔽。断网失败应保留输入，重试不产生重复内容。
6. **材质与布局**：地图顶栏和底部导航在滚动/移动时有原生材质；检查浅色、深色及大字号。减少透明度开启时应保持可读。浏览器截图不证明 iOS Liquid Glass 效果。

合成样本已导入 16 只，12 条带照片的档案复用四张合成猫图；没有伪造真实居民讨论。样本不代表实际猫位置。提交反馈用“步骤 + 实际现象”即可。

本轮发布检查：功能源 `b3dada3` 的[完整 CI](https://github.com/ZP151/anicare/actions/runs/34259012380)和[线上后端读写检查](https://github.com/ZP151/anicare/actions/runs/34259012406)通过。移动端 90 个套件、952 项测试通过；[主分支 CI](https://github.com/ZP151/anicare/actions/runs/34259667258)也通过。iPhone 结果待用户验证。

## 安装

使用已安装的 Sideloadly，选择本次交付的 IPA 和同一 Apple ID 更新应用。安装包路径、版本和构建结果将在交付后附于下方。不要先卸载旧应用，以免丢失尚未提交的本地草稿。

## 约 10–15 分钟的核心流程

1. **附近与档案**：保持默认“所有身份状态”（测试样本未假装为人工确认）。冷启动后看到明确标注的测试猫及照片；切换区域，再打开猫详情。记录页面是否仍显得拥挤、照片是否完整、图标是否清楚。
2. **毛玻璃**：在附近页上下滚动，查看内容经过底栏时的材质；查看地图浮层和照片上的按钮。系统“减少透明度”打开时应清晰实色，关闭后恢复材质。
3. **个人资料**：打开“我的”→编辑个人资料，修改昵称保存并返回。确认登录、语言和个人资料有各自清晰的页面层级，不再堆在首页。
4. **关注**：登录后关注一只测试猫；到关注列表打开它，关闭应用重开，再取消关注。
5. **目击**：从同一猫档案开始记录；中途保存草稿并返回，再恢复并提交。先测试无照片路径，随后可测试照片人工遮挡与上传；以回执显示的实际结果为准。
6. **照护**：为同一只猫记录已经完成的观察或补水，在“我的照护”确认。公共历史有延迟，本人记录和公共历史不要混淆。

有余力再切换深色、大字号和断网重试。反馈用“页面/图号 + 操作 + 实际结果”即可，例如“E01 保存昵称后返回仍显示旧昵称”。
