# v6：图片社区首页、清爽地图与真实消息

日期：2026-09-11。状态：用户已批准设计并要求 goal 驱动迭代，R1–R2 实施中。[10 个主要页面状态设计图](../design/ios26-social-v6/index.html)。

执行入口：[R1 布局与地图](../superpowers/plans/2026-09-11-v6-r1-layout-map.md)、[R2 媒体／首页／导航／互动](../superpowers/plans/2026-09-11-v6-r2-media.md)。当前 goal 到 0.4.0 IPA 实际交付才完成；R3 私信等后续按本表继续。下文原“待审阅／待实现”是方案制定时状态，实际进度记入两个执行台账。

## 已确认的产品方向

用户确认 0.3.1（7）的增量验收通过：16 只样本的单语言名字、独立测试标记、8 条示例帖／8 条回复、我的帖子。沿用 0.3.0 已暂时通过的原生毛玻璃、定位、搜索、报告与头像基线，不重复要求整套验收。

本轮将原 M6.3–M6.5 扩展为图片社区与消息阶段：紧凑排版、手势刷新、地图优先、猫头像标记、中央发布按钮、双列图片首页、多图详情与评论、用户私信、评论／点赞通知。用户明确选择先做用户私信与互动通知，管理员对话和 Bot 随后。视频需要独立交付，不能把播放器外观当成已支持视频。

保留产品重心：新加坡邻里围绕同一只猫的持续发现、讨论、报告与照护。首页的帖子可以关联猫与稳定邻里 ID，地图可以打开猫档案，中央发布仍能迅速记录目击。消息服务于邻里协作；不引入与猫无关的热榜、商城、钱包、直播或虚假活跃计数。

## 设计选择与现有代码依据

采用“首页／地图／＋／消息／我的”。首页合并现有社区浏览；附近成为首页的筛选，原猫发现能力保留为“看猫”筛选及地图入口。＋是打开发布面板的动作，不成为空白页面，也不覆盖返回前页面状态。报告迁到“＋ → 记录目击”，报告列表与草稿可从“我的”进入。

只保留旧五栏并局部缩小，无法解决附近和社区重复入口；一次性重写社交、视频与聊天，会让可验收版本等待全部子系统。因此按下面 R1–R5 分批实施，第一包交付能真实完成的图文与导航，再交付完整消息功能。

## 页面和交互规格

### 尺寸与材质

默认尺寸目标（pt，随系统字号缩放）：工具栏标题 20–22，信息流标题 15–16／最多两行，正文 16–17，辅助文字 12–13，图标视觉 18–22。列表左右留白 12–16，双列间距 8，图片圆角 10–12。44×44 点击区域保留；减少卡片内边距和重复说明，比把所有字缩小更有效。大字号或窄屏改成单列，不截断用户内容，不关闭字体缩放。

沿用钴蓝动作色、暖白内容面、人物头像与橘白猫 App icon。玻璃仅用于导航、悬浮地图控件和必要的底部输入条；照片和正文不覆盖厚重玻璃。浅／深色、减少透明度、减少动态效果均有可读状态。设计图是合成视觉参考，不能替代真机材质验收。

### 首页与帖子

H01：首页顶部“发现／附近”，右侧搜索；附近按选定邻里或用户主动定位后的粗粒度区域筛选，拒绝定位可手选。默认时间排序，暂不宣称个性化推荐。两列不同高度图片封面卡；标题、作者、真实点赞状态保持紧凑。文字帖仍可浏览，使用自身文字封面并标明文字，不给真实帖编造照片。8 条旧测试帖保留独立样本标记。

P01：帖子详情顶部作者和更多菜单，1–6 张图片横滑、页码、点图全屏；标题、正文、猫／邻里关联在下方，评论随后。图片保持原比例，封面可裁剪但详情完整显示。先显示已存在的真实点赞／评论；收藏、用户关注和分享入口只有功能实际完成才显示。

P02：评论可直接进入输入状态并回到所回复内容；主评论分页，子回复默认折叠。首期只做一层子回复及“回复某人”，禁止无限嵌套。评论点赞需要单独的数据实现；未完成时不显示图稿中的评论爱心。删除／举报／屏蔽沿用有效服务端规则。

C01：中央＋打开“发布帖子／记录目击／草稿”面板。取消回到原页与原滚动位置，不产生幽灵 tab。记录目击继续使用已验收的报告向导和加密草稿；不为社交照片伪造目击报告。

C02：多图发布，建议本轮上限 6 张，每张可移除、重排，首张为封面；拍照与系统图库复用权限入口，处理完成后预览。正文和图片先保存到本人本机草稿，发布时清晰显示进度；失败保留输入，重试复用同一请求身份。6 张是本次方案值，不表示已实现。

### 刷新与简化操作

首页、我的帖子、消息列表、评论列表在顶部下拉刷新，常态移除“刷新”文字按钮；空列表也可下拉。第一次加载与下拉刷新分别建状态，失败保留旧内容并给短提示。请求未结束时合并重复刷新，避免分页旧响应覆盖新列表。读屏可使用“刷新” accessibility action；网页保留紧凑图标入口。

地图画布下拉仍是平移，不能绑定全局下拉刷新。只有展开后的猫列表支持下拉；搜索／筛选变化重新加载可见数据。关闭用 xmark、筛选用 sliders，更多动作放 ellipsis；危险或不易理解的动作保留文字。图片横滑、列表拖动、返回手势之间不抢手势。减弱动画时保留明确状态变化。

### 地图

M01：地图默认约占安全内容区的 75% 以上；顶部为一行“邮编、建筑、街道”搜索和筛选图标，已选邻里用小 chip 显示。方位、规划区、邻里、HDB／Condo 类型收进筛选面板。底部三档：约 76pt 摘要、约 40% 猫列表、约 80% 完整列表；点抓手附近的展开按钮也可操作。

两个控件明确区分：“我的位置”用 `location.fill`，申请一次前台定位；“显示全岛”用 `arrow.up.left.and.arrow.down.right`，只调整视野，不再申请定位。地点搜索结果保留建筑类 pin；用户定位是蓝点，不能与猫头像混淆。

只替换应用自身的猫／社区覆盖标记，Apple 底图的地名和 POI 保留。猫头像约 28–36pt，优先展示公开档案头像；无照片用统一猫轮廓。全岛视角聚合为头像簇与数量，初始渲染预算约 24 个聚合标记，放大后再细分；计数来源于已载入公开活动，不代表全社区猫总数。集合更新、图片缺失、隐藏猫与选择状态都需要同步。

标记坐标仍来自允许公开的延迟、粗化活动／区域锚点。当前地图用规划区或邻里中心，不能把不同猫随机撒到楼栋来制造精确性。点击头像簇先打开对应区域猫列表，清楚标明“邻里活动”，再进入单猫档案；多只猫共享锚点时聚合。设计图上散布的头像仅表示视觉密度，不是要写入数据库的位置。

### 消息与个人页

N01：原社区 tab 迁成消息，顶部“互动／通知”两个紧凑入口，下方真实会话列表，预览、时间、未读状态。首次无会话给“从帖子作者发起对话”的可用引导；不填充假朋友、管理员或 Bot。消息功能未完成的过渡包将该位用于真实互动收件箱，不放不可点击的会话。

N02：从真实帖子作者的公开资料发起一对一文字私信；本人、已删除作者与系统样本没有该动作。支持发送中／已发送／失败重试、加载较早消息、拉黑和举报；不宣称端到端加密，不假装已读，不显示未接入的语音／视频通话按钮。陌生人首次发起只允许一条消息请求，接受后正常对话；拒绝与屏蔽可立即停止新消息。

N03：评论、回复、帖子点赞进入本人互动列表，点击回到目标帖子／评论。自己操作不通知自己，重复请求不重复通知，取消点赞／删除／屏蔽后不会通过通知泄漏已不可见内容。系统支持通知与互动分开；管理员和 Bot 在后续真正可用时再出现。

U01：紧凑人物头像、昵称、所属邻里、编辑与设置；“报告／关注的猫／草稿”快捷入口；下方“帖子／照片”网格。照片只来自本人已公开帖子附件，不混入头像、报告私图和未发布草稿。本人帖子与照片仍受退出、账户切换及删除影响。

## 后端与本地存储

保持现有 Expo／React Native、Supabase Postgres／Auth／Storage，新增能力不要求另建 AWS 主后端或引入 Tailscale 到普通用户访问路径。当前地图是 react-native-maps 1.27.2 的 Apple provider，继续复用，不换 expo-maps。

媒体：新增独立 community media 预约、上传、校验、附件关联与清理记录；每张图片限制解码尺寸／字节并重编码去除 EXIF，派生缩略图及展示图。帖子的附件集发布以数据库事务提交；对象存储上传与数据库无法做一个原子事务，先保持对象私有，全部合格后一次发布有效引用，失败对象按到期任务回收。上传有效期内被删除的对象也要在凭据过期后再扫一次，避免晚到上传复活。

已有公开帖子接口字段校验严格，新增附件／作者可发消息 ID／标题使用版本化接口或独立批量查询，旧接口原样保留。每页批量返回缩略图描述、反应与公开作者摘要，避免每张卡片单独请求造成 N+1。长期公开 URL 会削弱即时删除能力；读取时校验可见性，缓存期和撤销策略纳入附件实现，不承诺已经下载到他人设备的副本能被收回。

本地：沿用加密 SQLite／SecureStore，新增版本化社交草稿与待发送队列，账号 ID 绑定，图片文件沿用加密附件策略。升级不覆盖原报告草稿；退出清理会话 UI、订阅和敏感缓存，重入按服务端游标补齐。

消息：单独建 conversations、members、messages、message_requests、notification_events 与收件人状态；唯一会话参与者组合和 client_request_id 保证幂等。服务端从会话身份推导收件人并检查成员／屏蔽关系，不能相信客户端传来的 owner。Realtime 仅用于通知有更新，持久记录和重连补齐来自 Postgres；通道鉴权和成员权限均验证。未读从收件人的已查看游标推导。

推送：先交付应用内真实通知与消息同步。目前是免费 Apple ID 侧载，不将远程推送作为这批前置条件，也不声称锁屏可收到消息。APNs entitlement、签名和服务凭据有实际条件后单独接入；关闭应用期间新消息保留，重新打开后补齐。

视频：R5 再引入最长约 30 秒单视频帖、封面、转码、大小／时长限制、失败恢复和播放状态；短视频与多图帖先不混排同一附件集。优先明确转码执行方式与费用再实现，可评估现有 AWS Linux worker；不能只把未经处理的视频上传后直接公开。这里的限制是待验证方案值。

## 图稿与实现边界

两张图覆盖 10 个关键状态：H01/M01/C01/N01/U01 与 P01/P02/C02/N02/N03。地图筛选、展开列表、全屏图片、消息请求和设置继承此规格；报告向导、头像选择、隐私与删除页沿用已通过设计。没有重画全部历史子页。

生成图的个别符号不作为实现依据：第二张的 Map 图标应统一折叠地图；主图的 Bot／管理员示例行不会提前出现在发行版；评论爱心要等对应功能完成；发布 sheet 打开后不保留可点击的背景 tab bar。英文为画板排版，正式界面继续完整中英切换。

用户提供的五张小红书截图仅用于理解双列、评论、消息与个人内容页，不复制截图中的帖子、肖像或品牌资产进入产品。原文件保留在工作区 `rednote reference/`，未加入公开仓库；本稿合成图片使用内置 imagegen，提示词存于设计目录。

## 实现参考（2026-09-11 查询）

- [React Native RefreshControl](https://reactnative.dev/docs/refreshcontrol)：用于列表顶部下拉，绑定受控 refreshing 状态。
- [react-native-maps Marker](https://github.com/react-native-maps/react-native-maps/blob/master/docs/marker.md)：自定义子视图及 tracksViewChanges 的性能约束；远程头像不能直接假设支持 Marker 的本地 image 属性。
- [Expo Native tabs](https://docs.expo.dev/router/advanced/native-tabs/) 与 [custom tabs](https://docs.expo.dev/router/advanced/custom-tabs/)：当前原生导航与中央动作必须先做原生小样验证；若需自定义布局，继续使用项目原生 GlassSurface 并验收材质，不能把 CSS blur 作为 iOS 原生证明。
- [Supabase Realtime Authorization](https://supabase.com/docs/guides/realtime/authorization)：私有通道权限及 private 模式，配合持久消息的成员校验，不替代数据库授权。
