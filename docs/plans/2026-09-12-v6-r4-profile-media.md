# R4：我的照片与社区整理

沿用已批准 v6 的 U01。接续 0.4.2 私信与评论续聊；真机反馈随下一次测试合并记录，不要求重新审批设计。目标是让用户找回自己的贡献、整理照片并辨认所属邻里，推进 G4 与 G6。

## 实施顺序

1. **本人照片读取。** 基于已发布社区帖的附件，增加按当前登录身份分页的照片投影；保持现有帖子 9 字段与附件接口兼容。只包含本人当前可见的已发布照片，不把报告私图、头像、未发布附件混进相册。每个条目能回到所属帖子，删除帖子后刷新即消失。
2. **个人主页按 U01 收紧。** 人物头像／昵称／邻里集中在顶部；编辑和设置使用明确图标，报告、关注猫与草稿保留简短入口。下方为“帖子／照片”内容切换；空状态给发布入口，不加虚假的关注数、阅读量或收藏数。文字和图片区域保持可读，保留 44pt 触控范围和大字号适配。
3. **所属社区。** 复用现有新加坡规划区／邻里稳定 ID 与中英名称，允许编辑居住或常活动的邻里；地图临时浏览位置不自动覆盖个人资料。位置授权失败仍可手动选择，不混用 CDC、选区与 URA 边界。
4. **到期媒体清理。** 使用现有 cleanup-community-media 处理器与到期队列接入无人值守调度，凭据只留在服务端。保留上传凭据有效期内的延迟清理和重试，验证同一任务不会重复破坏有效对象。云端权限若暂不可用，前三项可独立形成下一安装包，调度状态明确记为未上线。

## 必要回归

- 两账户照片隔离、退出时撤掉旧预览、删除停止新读取；帖子多图顺序及回跳正确。
- 相册分页去重，刷新失败保留当前内容，迟到响应不覆盖新账户；旧报告和社交草稿仍能恢复。
- 邻里切换语言后 ID 不变，手选不会被迟到定位结果覆盖；编辑后重开保持选择。
- 清理使用到期／未到期／失败重试三个服务端场景，真实对象存储读回验证；不以任务返回 200 代替对象已清理。

每次功能修改跑相关测试；整合时使用已有 CI 和一次原生构建。仅对本批相册、个人页和社区选择做增量真机检查，保留 0.3.x 已通过结果以及 0.4.1–0.4.2 待测记录。

## 完成边界

本批不新增视频、推荐算法、用户关注关系或 Bot。照片网格服务于找回真实贡献；媒体清理是已发布功能的维护，不给普通发布流程增加人工审核。实际找回照片成功率、保存社区后的使用效果均在真机操作后记录，不用测试条目数替代产品效果。

## 0.4.4 增量

已接入基于本人帖子分页的帖子／照片网格、原帖回跳、公开昵称与版本显示，账号切换清理旧预览。独立照片分页 API、所属邻里编辑、设置收纳以及媒体调度仍未完成，不能将本切片算作整个 R4 通过。先随设备修正包交付，继续按上方顺序完成剩余项。

## 0.4.8 后的执行切片

用户最新要求覆盖早期“报告/关注/草稿”三入口：移除我的页 Reports 快捷项，保留设置中的报告历史；昵称旁铅笔进入独立资料编辑。0.4.8 已接通昵称与头像，不再由 Edit Profile 跳到设置。地图、六图网格和回执身份气泡先随本次设备修正交付。

接续顺序仍为：

1. **独立照片分页。** 当前 `ProfilePosts.tsx` 先按 20 篇本人帖子加载，再把每篇最多六张附件展开。新增按当前账号读取已发布附件的 API 与独立游标；保留图片序号及原帖回跳。用一批纯文字帖、六图帖、删除帖以及翻页时账号切换覆盖边界，避免“本页无照片”误报整个相册为空。
2. **个人邻里编辑。** 当前 user_profiles 没有个人邻里字段；需要带数据库迁移、owner 写入权限与稳定 ID 校验的完整切片。编辑页选择常活动邻里并保存；地图临时位置及新帖的一次定位不会默默写入个人资料。清除选择与切换语言均应保持可用。
3. **帖子/评论细节。** 按详情设计图集中作者、图片计数、简短猫卡与邻里/时间；评论层级保持紧凑，输入与键盘安全区作为回归项。沿用现有真实发布、点赞、评论 API，不伪造互动数。
4. **到期清理调度。** 延续上文服务端独立验证要求，前述 UI 交付不代表调度已上线。

以上剩余切片不因 0.4.8 的本地测试或原生构建通过而自动标记为完成。
