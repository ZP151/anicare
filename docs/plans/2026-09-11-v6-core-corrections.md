# 0.4.1：按真机反馈修正核心体验

状态：2026-09-11 本切片已实现、回归、部署并交付已核验的 0.4.1（9）IPA，见[交付记录](../reviews/2026-09-11-v6-core-delivery.md)。真机效果待验收。0.4.0 双列照片已通过，保留布局。此次直接执行已批准方向，不增加逐页设计审批。

## 验收事实与本次交付

| 用户反馈 | 实施结果要求 | 必要验证 |
| --- | --- | --- |
| 首页双列照片通过；附近切换仍弹选区 | 首页仅发现／附近，点击与左右滑动同步；主动进入附近时获取设备位置并匹配官方邻里 | 已授权、首次申请、拒绝、服务关闭、超时、境外；旧请求不能覆盖新选择 |
| 猫咪分栏价值不大 | 首页收敛；地图的猫头像、猫列表和档案入口保留 | 切换首页不丢导航；地图仍能打开猫档案 |
| 全岛地图被顶部挡住 | 按实际顶栏、底部收起面板与导航占用拟合官方新加坡边界 | 初次就绪与显示全岛；手动拖动后不被重置；搜索仍有效 |
| ＋窗口过大 | 原生短 formSheet，原生抓手与可中断关闭；保留三种发布入口 | 打开／取消仍回原页面、原滚动位置，无虚假 tab |
| 底栏玻璃回归失败 | 恢复真正的 iOS 原生导航材质，中央发布作为动作保留 | 原生 API 配置和构建；最后由 iPhone 确认材质，网页截图不算通过 |
| 字体图标仍偏大 | 收紧标题、辅助字、视觉图标与留白；保留 44pt 点击与系统字号 | 双列／大字体单列、长中英文、读屏标签 |
| Willow／Biscuit 缺图，样本单调 | 补两张既有缺图档案；目标 32 猫、24 帖，扩充侧面、背面、模糊、遮挡、多猫及模拟邻居 | 受控幂等升级、来源记录、真实匿名读回；多猫图用于帖子，不伪称单猫身份 |

0.4.0 原清单第 4、5、6 项由用户跳过，状态为「未测」，不记为通过，也不阻塞这次核心界面修正。相关代码发生变更时只做定向自动化验证；不要求用户补测整套历史清单。

## 实施顺序

1. 修复首页手势／定位、地图可见范围、原生导航和短发布面板，保持已通过的照片流。
2. 扩充明确标注的合成样本；模拟邻居只作为样本展示资料，不创建可登录假账户，不制造点赞或真实活跃量。缺图回归只保留少量明确用途样本，其他图片读取失败均有可见占位。
3. 合并后运行变更相关行为回归、类型检查和现有 CI；后端若有必要迁移一次部署，样本导入后实际读回。
4. 构建并校验 0.4.1（9），交付同一 Apple ID 覆盖安装。旧报告和帖子草稿保留。

## 本轮之后

R3 私信顺延到 0.4.2：真实用户私信请求、接受／拒绝、会话与消息恢复；评论／点赞通知沿用已接入能力，管理员和 Bot 后置。随后实现本人照片及到期媒体清理调度，再做视频。每批以可运行闭环交付，不要求把全部后续功能一次做完。

产品目标持续为「发现附近的猫 → 查看猫档案及邻里讨论 → 发布记录／收到回应」。本批以定位成功进入邻里、地图可见范围、发布取消保持上下文、图片正常展示为验收指标；合成样本不算留存或社区活跃。

设计依据：[已批准 v6 图稿](../design/ios26-social-v6/index.html)。除了恢复原生底栏材质，其他页面尽量保持该稿的构图与信息层级；不加入无关商城、热榜或复杂操作面板。
