# R3 / 0.4.1：真实用户私信与评论续聊

前置：0.4.0 的 R1–R2 已有实现；先完成部署、IPA 交付及本轮增量反馈。用户明确优先用户私信和评论／点赞通知，管理员与 Bot 后置。此文件是下一切片的执行顺序，不表示私信已实现。

## 交付动作

从真实帖子作者进入公开资料 → 发起一条私信请求 → 对方在消息中接受 → 双方文字往返 → 退出或断网重连后恢复。互动列表沿用 R2，新增评论子回复可定位到原评论。普通用户操作不增加人工审计。

## 最小实施顺序

1. **公开作者入口和私信权限。** 单独投影公开作者标识，保持现有帖子接口兼容；本人、合成样本、已删除作者不显示私信按钮。建立会话、成员、请求、消息与本人阅读游标。服务端从登录身份和成员表推导权限，不相信客户端 owner；同一对用户只有一个会话。先用数据库回归验证陌生人最多一条未接受请求、接受／拒绝、第三方隔离、双向屏蔽和重复发送。
2. **请求及发送闭环。** RPC 接受 client_request_id，超时重试返回同一消息；请求接收方才能接受，拒绝或屏蔽后停止新消息。删除或注销后的消息呈现与清理沿用既有账户处理规则，新增规则需在实现时明确。不给出未实现的端到端加密承诺。
3. **消息列表与会话页。** 消息 tab 展示真实会话和已有互动入口，未读由本人阅读游标推导。先实现游标补齐、分页、失败重试与应用前台刷新，再用私有 Realtime 提醒重新取数；Realtime 不能代替持久记录。显示发送中／已发送／失败，未接入对方阅读回执时不显示已读。
4. **原生待发送队列。** 复用现有加密存储和账号绑定，文字按会话和 requestId 持久化；切换账户立即撤掉旧界面及订阅，迟到结果不导航或写入新账户。已有报告与帖子草稿不迁移、不清空。
5. **评论续聊。** 保留原顶层评论，增加有父评论的回复查询与真实通知；通知返回仍可见的目标。删除、拉黑、撤回后不会从通知绕过可见性规则。
6. **一批交付。** 定向 SQL／API／路由回归后运行现有 CI，部署一次并构建 0.4.1；依据 0.4.0 真机反馈修正相关路径，不重跑没有变更的历史截图审计。

## 唯一 iPhone 的增量验收

- 账户 A 发给 B 一条请求，第二条在接受前受限；切到 B 接受并回复，再切 A 能看到真实内容。
- 发送时断网并重开，重试同一条不重复；向上加载旧消息后恢复网络能补齐新消息。
- 拒绝／屏蔽立即阻止新发送；第三账号越权由自动化覆盖。
- 从评论通知打开正确帖子及回复；注销、退出、账号切换后不残留其他账户内容。

免费 Apple ID 当前仅验应用内同步，锁屏推送不是本批依赖。视频、管理员、Bot、联系人导入及大规模推荐不在 R3。

## 产品目标

G4：发帖后找得到、收到真实回应并能续聊；G6：一次小范围功能回归、一份可安装包。记录请求接受到首次回复、失败重试和重连结果；无真实用户观察窗口时写“未测”，样本和自测不计活跃指标。
