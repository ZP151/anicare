# Iteration roadmap v4 — 猫主体社区迭代计划

> **For agentic workers:** 按本路线分批推进；每批展开具体任务计划后，使用 `superpowers:executing-plans` 或在明确采用代理协作时使用 `superpowers:subagent-driven-development` 执行。复选框仅在对应证据齐全时更新。

**Goal:** 在小范围用户研究前，交付“认识猫 → 阅读共同故事 → 补充相遇 → 关注 → 看到他人更新”的可安装完整体验。

**Architecture:** 复用现有猫身份、关注、帖子、媒体、草稿和照护能力；新增围绕猫的内容聚合、可更正的故事关联以及关注更新读取。保留故事、目击和照护各自的数据与权限边界，采用兼容旧客户端的增量接口。

**Tech Stack:** 现有 Expo / React Native / Expo Router、原生 Apple 地图与导航、加密 SQLite 草稿、Supabase Postgres / Auth / Storage、Jest / pgTAP 及既有 CI。

**Spec:** [猫主体产品重构设计基线](superpowers/specs/2026-09-13-cat-centered-product-design.md)。

日期：2026-09-13。状态：**C0 三页视觉目标、边界状态与 C1 契约已制作并走读；独立审查的五项修正已核对完成。C1–C3 尚未实现。** 这是跨批次产品路线，各批次的接口、迁移和测试代码在对应任务计划中具体化，不能把本文当成已存在 API 的说明。

## 1. 当前基线与优先级

当前已验收基线为 **0.4.13（21）**。用户本次确认最近几轮验收通过，含此前合并的 0.4.11/0.4.12；新报的帖子顶部加载标记单独修复。见 [设备测试单](ios-next-device-test.md)及 [本轮 C0 与修复记录](reviews/2026-09-13-v4-c0-refresh.md)。这些结果不授予正式试点就绪或研究效果通过。

本路线取代 v3、v6 中尚未执行的功能优先级；旧文档保留历史与仍适用的功能契约。新优先级为：阻碍核心使用的实际故障 → C0 设计与契约 → C1 猫主页和贡献 → C2 发现与回访 → C3 完整性与调研准备。具体版本号在出包时确定，不预留虚假的发布日期或 IPA。

既有私信、评论、个人照片和邻里能力继续可用。视频、管理员/Bot 新体验、进一步聊天扩展和脱离核心旅程的个人页精修暂缓。媒体清理、账户隔离、旧草稿兼容以及已发现的功能故障属于基础可靠性，不能因为转向而遗弃。

## 2. Global Constraints

- 执行时同时阅读 Spec 的全部语义边界；故事关联不等于身份确认、目击或照护事实。
- 首版每帖最多关联一只猫；未知或多猫内容允许暂不关联，未知分享需选择邻里。
- 复用 1–6 图、三列两行、照片编辑与重排、失败重试及账户绑定的加密草稿。
- 猫主页、相册和关注页只读取当前允许查看的内容；照片权限不因聚合而扩大。
- 故事关联更正、删除和隐藏的一致性从 C1 开始交付；不能全部推迟到 C3。
- 公开时间和地点沿用现有规则；新上传旧照片不能描述为最新目击。
- 保留中英、浅深色、大字号、减少动态效果及至少 44pt 操作区域；原生玻璃和触控行为由设备验收。
- 旧帖子和旧草稿可继续打开；未关联历史内容不自动猜测身份，不复制或删除原帖以制造新故事。
- 正式公开试点的 AI、媒体、隐私和运营准入条件不因本路线自动取消。AI 是辅助能力，当前效果仍未测。
- 测试和演示数据显式标注并与真实产品指标分开；不制造照护、真实位置、活跃或情感回访证据。

## 4. C0 — 确定最小视觉目标与数据契约

**结果：** 为 C1 提供可以直接实施的页面目标与边界，不启动全应用改版。

- [x] 对照现有 iOS 页面与 v6 图稿，制作猫主页、选猫发布、发布成功三个相连的目标页面；同时画出未知猫、无故事、加载失败和关联不可用状态。
- [x] 猫主页先呈现身份与故事；主按钮为分享相遇，保留目击、照护和纠错入口；不新增热榜、关系等级、自动性格或 AI 传记。
- [x] 明确点击分工：猫身份进入猫主页，故事进入原帖，作者进入作者资料。未知内容没有伪造猫身份。
- [x] 写出 C1 任务计划：每个接口的输入、返回值、分页游标、错误、权限、幂等键和既有客户端兼容方式；列出实际新增迁移与测试文件。
- [x] 将“帖子作者的猫关联声明”与“档案已审核身份”分别展示，明确作者更正和第三方纠错的权限。
- [x] 用一组标注演示场景走读三个页面，记录视觉目标与决定，随后进入 C1。

**退出标准：** 页面主次、已知／未知猫路径和关联语义明确；已有用户授权及具体视觉选择按会话事实记录，不重复索取同一项批准。完整首页和相册细节随各自批次设计。

## 5. C1 — 猫主页与共同贡献（第一可安装增量）

**用户结果：** 两个人的相遇故事可以在同一猫主页汇集；新用户可以先分享未知猫。

### C1.1 猫主页故事读取

- [ ] 先补失败测试：同猫跨作者聚合、不同猫不混入、无内容、分页重复时间、隐藏／删除／屏蔽过滤、缺图与加载失败。
- [ ] 实现按猫批量读取可见故事与媒体摘要，稳定分页；展示作者与来源，点击原帖继续评论。照护和目击暂以独立入口保留。
- [ ] 重构猫主页布局，增加分享相遇动作，保留关注、照护、目击及纠错。不能把原本保护的报告素材放入故事列表。
- [ ] 定向测试通过后进行独立差异审查，重点核对新增聚合没有扩大可见性。

### C1.2 选猫、草稿与发布回流

- [ ] 先补失败测试：路由预选、改选、取消关联、未知猫加邻里、草稿重开、目标猫已隐藏、账户切换、超时重试不重复发布。
- [ ] 新增可见的选猫操作，优先提供关注和邻里查找；最近查看如引入缓存，按账户隔离、退出清理，不视作已关注。
- [ ] 已关联发布后显示查看猫主页和查看原帖；未知发布回到原帖，提供以后补充关联的操作。
- [ ] 复用既有六图编辑、上传、幂等发布和草稿版本兼容；目标猫失效时保留输入并允许重新选择或改用邻里发布。
- [ ] 定向测试与独立审查通过；新增能力不能破坏无图文字帖和旧草稿。

### C1.3 最小更正与一致性

- [ ] 先补失败测试：本人关联 A→B、取消、未知→已知、重复请求、非作者修改拒绝、旧请求覆盖新选择、猫不可用、删除后不能复活关联。
- [ ] 实现本人更正操作及可追溯变更；第三方沿用纠错／举报入口。通过服务端版本校验防止迟到请求覆盖新决定。
- [ ] 更正后刷新相关猫故事和帖子上下文；原帖、作者、评论和图片身份保持一致，不以复制帖子模拟迁移。
- [ ] 自动检查和一次两账户真机旅程通过后交付 C1；无网络时显示失败／待确认，不能先宣称已更正。

**C1 设备验收：** A 从猫主页发一段故事，B 为同猫补一段；两者汇集且可进原帖。再完成未知猫发布、补关联、改关联、删除与草稿恢复。设备使用演示猫时注明它不是真实动物记录。

**依赖与下一步：** C1 只依赖现有身份、社交和媒体底座；不等待 AI、推送或视频。C1 的关联、可见性与读取契约稳定后进入 C2。

## 6. C2 — 首页发现与关注回访（第二可安装增量）

**用户结果：** A 关注猫后，B 的新贡献能在 A 再次打开应用时被发现。

### C2.1 发现入口

- [ ] 明确发现／关注的视觉目标，邻里筛选留在发现内。第一次进入默认发现，之后按账户保留已选入口。
- [ ] 先补失败测试：关联猫卡片可进入猫主页，原帖仍可进入，未知内容正常显示，邻里筛选、文字帖、大字号和账号切换不退化。
- [ ] 实现照片卡上的猫身份入口与作者署名；不要求所有发现内容必须绑定猫，不按人气猫排名。

### C2.2 关注更新与阅读进度

- [ ] 编写服务端契约和失败测试：按猫归并、跨猫分页、无新增、首次关注、取消关注、晚公开内容、关联更正、删除／屏蔽／身份不可用、账户隔离。
- [ ] 更新依据为允许该用户查看的新故事／新关联进入该猫故事流的事件；使用服务端稳定事件序列，不能用客户端时间或原帖创建时间推算全部更新。
- [ ] 首次关注展示已有故事，但不把全部历史标为未读；关注后的新可见事件才产生新提示。本人贡献可显示，不制造自己的未读提醒。
- [ ] 阅读进度推进到本次实际展示的事件边界；加载后又到达的新事件仍保留未读，简单返回页面不一键清掉尚未展示的更新。
- [ ] 同猫多条更新适度归并，点开定位到相关故事；更正归属后旧猫不保留残余新提示，新猫可将新关联作为新故事更新，不能称为最新目击。
- [ ] 应用内读取和进度重开可恢复；取消关注停止更新，重新关注重新建立起点；失效内容从摘要和计数移除。
- [ ] 独立审查分页、权限和阅读竞争；定向测试及两账户真机验证通过后交付 C2。

**C2 设备验收：** A 关注猫并离开，B 发布，A 重开看见更新并进入原帖。之后验证读过状态、第二条新内容、取消关注、无新增、未登录发现和跨账户隔离。远程推送不是此批依赖。

## 7. C3 — 相册、管理与调研准备（第三可安装增量）

**用户结果：** 用户能持续阅读、找回及管理关系中的内容，完整旅程具备真实研究条件。

- [ ] 猫相册聚合可见关联帖子附件，分页后可进入原帖正确图片序号；缺图、删除、更正猫关联后刷新一致。测试报告私图、草稿、头像不会混入。
- [ ] 个人页突出关注的猫及本人相遇内容；保留全部旧帖和照片管理路径，普通邻里帖子不自动改称目击或相遇。
- [ ] 完善更正后的阅读定位和反馈，覆盖连续更正、回退、失败重试；C1 已交付的基本纠错、删除和权限不能拖至此批才实现。
- [ ] 组织至少 4 只明确标注的演示猫，每只有至少 2 位演示贡献者及跨时间故事；旧演示图若不代表同猫，不直接重标为同猫连续实拍。
- [ ] 演示覆盖未知猫、无新故事、旧照片新上传、错关联后更正和多猫照片；不批量伪造关注、照护、评论或用户活跃来充实界面。
- [ ] 两个真实测试账户完成端到端旅程；完成中英、浅深色、大字号、断网恢复、删除和换账户增量检查。
- [ ] 对照下节清单记录是否具备研究条件，再准备邀请和研究任务；实际招募、联络与消息发送另按用户明确授权执行。

**退出标准：** C1–C3 的关键旅程真实可操作，没有阻断分享、关联纠错、回访或旧数据恢复的问题。不能用“页面已存在”代替通过。

## 8. 执行与验证约定

每个子任务按“行为失败测试 → 最小实现 → 定向通过 → 独立审查 → 有意义的小提交”执行；代码步骤和实际测试代码写入对应批次计划。路线和普通文案的改动只做文档检查，不为此新增实现镜像测试。

已存在的测试入口示例（工作树根目录）：

```powershell
pnpm --filter @animalhelper/mobile exec jest --runInBand --runTestsByPath src/api/cat-route.test.tsx src/api/community.test.ts src/community/SocialComposer.test.tsx src/community/post-draft.test.ts src/community/post-publisher.test.ts
pnpm --filter @animalhelper/mobile exec jest --runInBand --runTestsByPath src/community/SocialHome.test.tsx src/api/follows.test.ts src/following/following-journey.test.tsx
pnpm --filter @animalhelper/mobile typecheck
```

新增聚合、关联、更新及相册测试加入各批的定向命令；上述旧测试不能单独证明新增能力正确。涉及 SQL 时运行对应 pgTAP 及既有数据库契约，执行方法见 [回归手册](regression-playbook.md)。合入／交付运行 `pnpm verify` 和现有必需 CI；同一候选复用有效证据，随后做原生构建、IPA 来源核验和一次增量设备验收。未运行的检查明确记未运行。

同一工作树仅一个实现者写代码；需要协作时才并行独立只读审查。遵守项目模型路由政策，容量或额度失败不降低 TDD、审查或验收标准。文档计划完成不自动触发实现、部署、推送或真实用户联络。

## 9. 调研前验收与后续价值指标

### 必须先通过的产品旅程

- [ ] 新用户能从发现找到猫主页，理解故事由不同人贡献。
- [ ] 已知猫的分享汇入正确主页；未知猫可以继续发布并以后更正。
- [ ] A 关注、B 分享、A 回来看到更新、A 继续参与的完整链路成立。
- [ ] 更正和删除后，旧猫主页、相册和关注摘要不残留错误内容。
- [ ] 旧帖子、旧草稿和旧报告仍能访问；换账户不暴露前一人的草稿、关注或阅读进度。
- [ ] 样本和真实内容分开；用户能区分故事更新、实际目击及已完成照护。

### 小范围研究时再测，当前均未测

| 指标 | 定义与用途 |
| --- | --- |
| 同猫贡献成功率 | 给定认识的猫，完成正确关联分享的人数／实际尝试人数；未知和失败单列 |
| 多人连续故事猫数 | 观察期内至少两位不同真实贡献者留下有效关联故事的猫数；不称为已确认身份或已照护猫数 |
| 关注更新抵达率 | 有可见他人新故事且回访的参与者中，实际找到新故事的比例 |
| 7 日有用回访率 | 有完整 7 日观察窗的参与者中，自发回来读到他人新故事或补充／更正有效内容的人数比例；访谈催促返回另列 |
| 关联纠错成功率 | 实际尝试更正中成功且所有入口一致的次数比例，记录失败原因与耗时 |

初期用自愿任务观察和最小必要账本取数，不先建设第三方追踪平台。不把“会不会喜欢”当作留存证明；原有照护北极星指标与正式试点条件继续保留，新故事指标不能替代它们。

## 10. 暂缓范围与恢复条件

| 暂缓项 | 重新评估条件 |
| --- | --- |
| 视频、更多聊天形态、管理员/Bot 新入口 | 核心回访路径成立，且用户观察显示明确缺口 |
| AI 拟人化对话、自动传记、性格评分、亲密度等级 | 本轮不立项；需要独立证明真实性、价值和参与负担 |
| 多猫关联、协同别名编辑、复杂关系图 | 单猫路径稳定且研究反复出现现有模型无法表达的需求 |

| 大规模推荐或分析平台 | 有真实内容密度及明确决策需求后再评估 |
