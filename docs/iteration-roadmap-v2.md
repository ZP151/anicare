# Iteration roadmap v2 — 2026-09-05 功能优先修订

> **2026-09-07：功能执行顺序已由 [v3 产品交付路线](iteration-roadmap-v3.md) 替代。** 全项目评审发现报告身份意图、确认后建档和照护闭环缺失，因此先做 v3 M1，再做关注。本文保留为历史；R0/R1 发布技术约束仍供引用，不再按下文“下一项 R2a”启动新任务。目标状态见 [产品台账](product-goals.md)。

本路线替代旧 Sprint 0–8 的执行顺序，保留产品章程和隐私不变量。代码核对基线为 `codex/hosted-gate-2b` / `6797215`，历史环境结果见 [验收报告](reviews/2026-09-05-project-acceptance.md)。本轮核对本地源码、计划和 CI 定义，没有重跑远端、编译或实机；历史结果不代表当前发布就绪。

**执行决定：下一项是 R2a 猫关注闭环。R0 作为按需交付支线，不再要求全部整改、实机与运营验收完成后才开始功能开发。** 当前仍只使用合成数据；此调整不放开设备候选、公开媒体、AI 或真实用户准入。

## R3a / R2b / R5：延伸可用功能

**R3a 账户基础：**拆清匿名、已登录和可贡献状态；My Reports/草稿链接复用已有路由。显式输入公共名称或使用不含邮箱的默认值，重复成年确认不覆盖已选名称；错误映射固定中英文文案。实现退出，账户切换清私有视图并阻断迟到写回；待清理媒体引用继续留在正确账户边界。测试覆盖名称不被覆盖、退出失败、换账户和返回草稿。

**R2b 区域关注：**在 `CoarseAreaDetailSheet.tsx` 接通禁用按钮，复用 Following 增删/分页与账户策略。服务端按既有地图策略校验 H3 resolution 9 和支持范围；列表能重新定位粗略区域并打开详情。无公开活动显示空态，不编造猫数据，不因无活动阻止取消。无需位置权限即可完成；不增加精确 pin 或路线。

**R5 发现：**修改 Nearby/Map 和 feed adapter，把单猫展示补成可遍历列表，连接已有 cursor；加载更多去重、刷新/重试、返回保留筛选。首版支持区域和身份状态筛选；原 RPC 参数不足时新增窄参数/契约，不用只筛当前页冒充全量结果。搜索、复杂排序、通知流后置。大字/读屏、中英、reduced motion/transparency 和地图 fallback 按改动范围验证，复用 `theme.ts`，不统一重做所有页面。

## R3b / R4：隐私和审核功能

**R3b 额外实现范围：**新增 owner 认证的账户删除请求和本人状态读取，服务端持久化并幂等接收，由受信服务执行账户删除及既有 erasure/outbox 清理。客户端不持有管理密钥，不把删 profile 当成整个账户删除完成。区分已接收、执行中、失败待重试；全量完成须有账户、媒体及相关清理结果。账户失效后的本地回执不保存 token/私有数据，不继续依赖已删除账户查询；完成通知渠道随受控运营流程落实，不新开匿名详情查询接口。

访问、更正、撤回先提供实际受理的联系/请求入口及说明；没有真实受理渠道时明确 unavailable，将责任人/渠道作为该入口启用条件。自动导出/通用工单平台后置。训练默认关闭，不做无后端意义的同意开关。删除、撤回与身份 job/媒体联动必须验证；本地与对应 hosted 验收各做一次并复用。

**R4 产品部分：**复用 admin session/角色和 decision action，补受审私有媒体读取与 My Reports 处理结果。无材料权限、已回避或已撤权时拒绝读取/决定；服务端记录必要的特权读写审计。业务审计日志是产品安全能力，不属于要删除的流程性重复审计。

R4 环境部分只补候选尚缺的 anonymous/owner/stranger/admin/recused reviewer、公开延迟、block、并发和撤权场景；已有切片验证直接索引。删除/事故/SLA 演练与真实用户准入共用适用记录，不在 R4 和 R7 原样各做一遍。

## R6 / R7：远期范围与真实用户准入

AI 和试点不进入当前执行队列。R6 启动时按真实依赖拆小：许可/同意 manifest 与撤回、animal-disjoint/open-set 离线基准可先行；模型结果有用且有人工审核承接后，才接 owner request/status/cancel/select、lease-bound broker/worker 和严格回调，再交付人工选择/独立 reviewer UI。避免先建完整 worker 平台再寻找数据。

AI 仍可 skip/cancel/unknown，worker 不直接确认身份，旧 service proposal bridge 永久禁用。Recall@3 ≥85%、unknown rejection ≥80%、unknown false match ≤5% 保留；合成数据不满足质量门槛。无 AI 人工版试点须明确修改产品范围与成功标准，不能标为 AI MVP 完成。

R7 以 [launch checklist](singapore-launch-checklist.md) 为唯一发布清单入口，涵盖设备、公司/DPO、隐私/权利、商店签名、事故响应和审核 SLA 等既有要求，不在每轮复制。公开媒体仍待可信服务端 residual validation；自动检测和相关实机要求仍开放。本文不提供新的法律结论，也不批准真实用户准入。

## 精简后的交付规则

1. 每切片交付可走通的用户流程及恢复路径，测试围绕权限、幂等、账户隔离和关键失败；文案/导航/无障碍随功能完成。已满足的检查不重新立项。
