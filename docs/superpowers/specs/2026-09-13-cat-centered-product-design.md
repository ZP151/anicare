# 猫主体产品重构设计基线

日期：2026-09-13。状态：用户已认可产品方向，并要求据此编写最新迭代路线；本文记录产品结构与范围。具体页面图稿、实现和设备结果分别验收，不将方向认可扩大为像素稿或功能通过。

## 产品承诺

让一只现实中的社区猫，被不同的人持续认识、记住和关心。猫是持续身份与故事的组织中心；用户是有署名的贡献者；帖子是一次表达及其讨论的载体。照护是关系加深后可进入的能力。

核心旅程：认识一只猫 → 看见大家留下的故事 → 分享自己的相遇 → 关注它 → 再次看到他人的更新 → 继续参与。

首批用户假设：经常遇见、能够认出几只社区猫的居民，以及提供连续认识和照护背景的照护者。产品结构先做成可体验版本，再开展小范围研究。工程验收不能证明用户愿意回访。

## 产品结构

1. 猫主页：照片、名字、已有别名、粗略邻里与简洁身份状态；主内容是跨贡献者的故事；相册、身份资料及允许公开的照护记录作为进一步了解的入口。主操作为“分享与它的相遇”，目击、照护和纠错保持可达。
2. 发布：沿用照片、正文、草稿与可靠上传；新增明确的关联猫入口。从猫主页进入时预选且可更改，从中央入口可按关注、最近查看或邻里查找。可以暂不确定身份；已关联发布后提供猫主页和原帖入口。
3. 首页：发现／关注。发现保持照片浏览，关联猫的身份与主页入口更突出，邻里是筛选条件；关注按猫归并新故事。首次使用进入发现，之后按账户记住用户选择。
4. 互动：保留原作者、原帖及评论。猫更新来自真实且允许查看的贡献，不使用猫的口吻编造需求、健康判断或“想你了”等事件。
5. 我的：优先暴露关注的猫与本人相遇内容。未关联或不属于相遇的旧帖子仍可在原有管理入口找到，不把所有帖子强行改写成相遇。

## 关键语义与边界

- 单只猫关联是首版范围。多猫照片可暂不关联；不要求选一个错误对象才能发布。
- 未知猫分享必须有选定邻里，沿用当前“猫或邻里至少一个”的发布条件；公开内容沿用原有媒体与位置规则。后续关联不能绕过既有身份确认流程。
- 普通故事关联只是贡献者的关联声明，不自动生成已核实目击、照护、猫身份或身份确认。界面区分故事关联与档案身份状态。
- 作者可补充、取消和更正自己帖子的猫关联；其他用户可提出纠错或举报，不能直接修改他人归属。第一批即提供基本更正能力。
- 投稿者不拥有猫档案。已有别名可展示；公开新增别名、档案协同编辑和身份合并工作台不属于本轮。
- 上传时间、新故事公开可见时间与实际相遇时间分开。旧照片新上传可算新故事，不算新的实际目击；只显示允许公开的时间精度。
- 没有新内容表示没有可见新内容，不等于猫失踪、饥饿或异常。
- 猫相册首版仅聚合当前允许访问的关联帖子附件。报告私图、审核证据和本地草稿不自动进入公开相册。
- 删除、隐藏、屏蔽、更正关联与身份失效要同步作用于故事、相册、更新提示及计数。不可见内容不能通过摘要泄露。
- 显示层可组合故事、目击和照护入口；底层保留各自事实类型、权限和媒体生命周期，不复制三套事实到一个万能帖子表。
- 复用现有中英、浅深色、大字号、减少动态效果、至少 44pt 触控区域及已验收原生导航。六图三列两行、编辑、重排和草稿恢复继续作为发布基础。
- 社交重构不撤销位置延迟与粗化、人工身份确认、删除权利以及正式试点的 AI/媒体等既有准入条件。

## 调研前的成功标准

两个真实测试账户围绕同一只猫完成跨人贡献和回访，入口无需解释；未知身份可继续分享，更正与删除会真实生效，换账户不会混入上个账户的关注或阅读状态。演示数据始终显式标注。

此标准只表示产品已可用于验证方向。是否产生牵挂、有用回访和实际照护价值，需要后续真实研究，当前均未测。
