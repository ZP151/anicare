# WhiskerCommons Pilot Gate 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the current Sprint 2–3 branch into a reproducible Pilot Gate 1 release-candidate foundation with an applicable PostgreSQL 17 schema, least-privilege native configuration, retryable encrypted local storage, locked Edge handler checking, and a secret-free internal EAS build contract.

**Architecture:** Keep every existing media/privacy invariant and add five narrow release boundaries around it: an immutable UTC retention deadline in PostgreSQL, a pure Expo configuration policy plus bounded CLI adapter, a focused encrypted-database initialization module, deterministic CI input discovery with a Deno lock, and a pure EAS contract policy. Each boundary is independently testable and committed before the final all-repository and GitHub Actions gates.

**Tech Stack:** PostgreSQL 17 + pgTAP, Supabase CLI 2.84.2, Expo SDK 57, React Native 0.86.3, TypeScript 6/Jest 29, Node.js 22, Deno 2.9.5, pnpm 11.19.0, EAS CLI 22.6.0, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-27-pilot-gate-1-design.md`

## Global Constraints

- Preserve reviewed-media encryption, owner binding, receipt binding, revision/lease CAS, bounded plaintext lifetime, and quarantine-before-delete behavior.
- Never log or commit a source URI, plaintext image, access token, signed capability, Storage path, precise coordinate, credential, project secret, or environment value.
- Invalid stored database keys fail with `secure_offline_storage_key_invalid`; never delete, replace, or log them.
- The pilot remains gallery-only: no generated Android `CAMERA`/`RECORD_AUDIO`, no iOS camera/microphone descriptions, and no background/always location descriptions.
- Retain foreground location, photo-library selection, scheme `animalhelper`, bundle/package `sg.animalhelper.app`, and `expo-sqlite` with `useSQLCipher: true`.
- Align exactly the thirteen Expo-reported direct packages; do not broaden the dependency upgrade.
- Pin Supabase CLI `2.84.2`, Deno `2.9.5`, pnpm `11.19.0`, Node `22`, and EAS CLI `22.6.0`.
- Pin the mobile-only TypeScript script runner `tsx` to `4.23.12` and commit the pnpm lockfile.
- Set `DENO_NO_PACKAGE_JSON=1` for Deno dependency operations so Deno cannot rewrite or absorb the pnpm monorepo package graph.
- This gate does not claim hosted Storage, two-session concurrency, physical-device behavior, signing, hosted staging, operational/legal drills, or real AI identity accuracy.

- [ ] **Step 2: Implement the focused initialization module**

Use exactly 64 hexadecimal characters for a stored key:

```ts
const DATABASE_KEY_PATTERN = /^[0-9a-f]{64}$/i;
```

`loadOrCreateDatabaseKey` must:

1. throw `secure_offline_storage_unavailable` when unavailable;
2. validate a non-null stored value before returning it;
3. generate exactly 32 bytes and lowercase-hex encode them when absent;
4. store only the generated valid key;
5. never log or overwrite an invalid stored value.

Implement retryable single-flight without wrapping successful promises:

```ts
export function createRetryableSingleFlight<T>(open: () => Promise<T>) {
  let inFlight: Promise<T> | null = null;
  return () => {
    if (inFlight) return inFlight;
    const attempt = open();
    inFlight = attempt;
    void attempt.catch(() => {
      if (inFlight === attempt) inFlight = null;
    });
    return attempt;
  };
}
```

`openEncryptedDatabaseWithDependencies` must load/validate the key before opening SQLite, then call `applyKey`, then `initialize`, and return the database. Web must fail with `secure_offline_storage_unavailable` before any dependency call.
