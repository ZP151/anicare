# C1 验收修正实施计划

> 使用 executing-plans 按任务推进；单工作树仅主代理写入，独立只读审查。用户已明确要求清理旧样本、补差异图片并固定顶部栏，继续既有设计授权。

**目标：** 首页现成样本即可进入猫主页共同故事，照片与身份一致；详情页滚动时身份及返回操作始终可见。
**技术：** React Native / Expo、Supabase SQL、TypeScript 样本导入器。
**设计依据：** 2026-09-13 用户四张拒收截图及 v4；保留双列首页、单行玻璃导航、报告和六图编辑。

## 1. 数据与媒体
- [ ] 盘点 tests/test-samples-provisioner、旧样本 ID、托管 manifest、媒体引用及猫关联；仅白名单演示内容可退出可见集。真实用户内容、回复与上传不按名称或正文模糊删除。
- [ ] 生成身份稳定的四只演示猫，各自至少两位演示作者、独立照片与跨时间故事；另留明确未知／多猫样本。不把不同猫旧图随意改成同一身份。
- [ ] 新版声明式样本清单、素材来源与哈希；保留旧 catalogue 身份稳定，新增独立版本。清理使用幂等、严格碰撞检查；真实引用的旧猫保留兼容入口。
- [ ] 导入前 dry-run；新增/媒体验证完成再退役旧演示显示，重复运行不复活、不覆盖用户更正；公共端核对关联、照片可读、故事作者差异。

## 2. 固定身份栏与入口
- [ ] ScreenScaffold 的 leading 返回栏默认放滚动区外；自定义 header 仍唯一，已有原生栏不重复；标题及简短副标题在同一栏。
- [ ] 帖子顶部合并返回、作者头像／名字、明确猫关注、分享与更多；猫名胶囊和首页猫身份入口可直达猫主页。未知帖不伪造猫身份。
- [ ] 猫主页固定返回／猫身份／关注／分享，照片留滚动内容；消息及对话、评论、列表复用或核对固定栏。可分享公开帖子和猫链接，私密会话不生成公开分享。
- [ ] 先写行为回归：返回栏不在滚动区、单一 header、长名字收缩、用户切换、不关联帖不出现关注猫、分享不带私密内容；运行受影响测试。

## 3. 交付
- [ ] 全量检查、独立差异审查、托管样本前后清单核验、双作者同猫公共读取；原生候选及来源核验。
- [ ] C1 0.4.15 记录不通过，静态刷新及此前基本通过保留；下版仅要求有明确入口的完整主路径，未做的设备项继续待测。
