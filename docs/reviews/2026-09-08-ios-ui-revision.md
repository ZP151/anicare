# iPhone 首次验收与 UI 修正

用户已用 Sideloadly 安装并打开 0.1.0（1），但未开始功能验收；视觉验收不通过。反馈是文字过多、图标使用不足、审美普通、Profile 缺少统一结构、看不到预期的 iOS 26 玻璃效果。安装成功不等于产品合格。

用户选择：**iOS 原生精致风，系统图标、分组列表、克制的 Liquid Glass**。

## 0.1.1（2）：先修每天都会看到的界面

- iOS 五个一级入口改用 Expo Router NativeTabs 和 SF Symbols，由系统呈现标签栏材质；不再把 94% 不透明背景覆盖到自制玻璃底栏。Android/Web 保留已有导航。
- Profile 改为账户概览、我的记录、偏好与隐私、账户分组；图标、行高、分隔线、字重、点击反馈和深浅色一致。登录表单由用户展开，登录后移除；贡献者确认只在仍需确认时显示。
- 昵称入口真实读取与保存当前用户的 public_name，使用已有 owner RLS；不改邮箱，不伪造头像上传或账户资料能力。账户变化清空输入并拒绝旧异步结果。
- 保留报告与草稿、照护记录、语言切换、隐私请求、退出和报告登录后续办；AI 的静态说明不再占据 Profile 首页。
- 页面容器使用原生安全区和自动滚动边距；键盘操作不再吞掉首次按钮点击。保留示例内容的真实标识，不把它误删为装饰文案。

本批没有重做所有页面。Nearby / Map 的内容层级、报告表单和猫档案的图片展示是后续切片；尚无真实许可猫图库，不用虚构社区数据装饰页面。

## 必要回归与手机验收

本地先复现登录表单常驻问题，再验证修正；覆盖登录展开、账户切换清空、昵称更新、旧响应隔离、退出失败、贡献者姓名不被确认动作覆盖，以及报告续办、猫详情和导航契约。没有因纯界面改动重新部署数据库。

手机先做四个短场景，失败只记录版本、步骤与实际结果：

1. 冷启动，五个入口可切换；iOS 导航在滚动时可见且不遮住操作。检查系统图标和浅色/深色 Profile。
2. 在“我的”登录；登录入口消失，昵称保存后重新读取一致；退出后私有输入立即消失。
3. 新建一条合成报告，手选粗略区域，提交后在“我的报告”找到同一回执。
4. 保存未完成草稿，关闭并重新打开 App，继续同一草稿；断网失败提供可理解的恢复入口。

随后才测需要公开档案/独立审核的照护、关注与身份闭环。当前所有手机功能结果仍为 **NOT RUN**；新版本的原生显示也必须由实际截图/手机观察验证，单测和代码评审不作为视觉验收通过。

## 产品目标追踪

- G6：首次安装完成；首次视觉验收失败，本批修正导航与账户界面。
- G1/G3/G4：实现与回归证据保留；真实手机功能和用户价值尚未测。
- 下一选择以手机阻塞和用户可完成的动作决定；不新增全仓审计、设计评分门禁或无数据 AI 功能。
