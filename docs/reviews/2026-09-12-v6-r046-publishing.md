# 0.4.6（14）发布与目击修复

用户确认 0.4.5 验收 1、2、4、5、6 通过；第 3 条真实发布、目击照片保存与遮挡体验未通过。截图显示新帖子进入即草稿失败，目击选择照片后在私密保存时失败。

## 原因与修复

安装的 Expo SQLite 57 `SQLiteDatabase.withExclusiveTransactionAsync` 在 `Transaction.createAsync` 中使用 `useNewConnection: true`；新连接不继承主连接的 SQLCipher key。帖子首次保存与目击照片 journal 保存都使用这个 API，普通报告文本保存则使用已加密主连接，解释了部分路径可用而两个保存路径失败。

新增共用事务适配器：独立连接先设置经过校验的 key、外键和 busy timeout，再 BEGIN IMMEDIATE；成功提交，失败回滚，最终关闭，不降级明文，不清除已有草稿或密钥。两个失败路径均接入。用模拟原生独立连接的回归先复现 `file is not a database`，修复后通过；独立审查检查了 Expo 的 TS 与 iOS 实现，无阻断项。实际手机写入仍待覆盖安装复测。

另修复目击 journal 失败后提前清理处理照片的问题：当前页面保留照片供重试；成功、换图、离开仍由原有缓存生命周期清理。重试不要求重新选图。
